# 🧩 LoRA：用低秩适配微调大模型

[大模型后训练](/tutorials/llm-post-training)里的 SFT、DPO、RLHF，默认都会更新模型的**全部参数**。这对一个几十亿甚至上百亿参数的模型来说，代价很高：每个任务都要存一份完整的权重副本，训练时要同时放下参数、梯度和优化器状态，部署时也很难为每个场景各挂一个模型。LoRA（Low-Rank Adaptation）给出的是一个很轻的替代方案：**把原权重 $W_0$ 冻住，只在旁边加一条小小的低秩旁路，训练时只更新这条旁路。**<Cite n={1} />

> 💡 **关键洞察**：LoRA 的全部设计可以压缩成一句话——**用两个小矩阵的乘积 $BA$ 去近似全量微调的权重更新量 $\Delta W$**。冻结 $W_0$ 让原始能力不被破坏；把 $\Delta W$ 限制成低秩让参数量骤降；初始化时令 $B=0$ 让训练起点与原模型完全一致；训练完再把 $BA$ 合并回 $W_0$，推理时连旁路的计算都省掉。

## 全量微调为什么贵

假设某一层的权重是 $W_0 \in \mathbb{R}^{d \times k}$。全量微调会把它变成 $W_0 + \Delta W$，其中 $\Delta W$ 和 $W_0$ 一样大。对一层而言这只是多存一个矩阵，但对整个模型来说，问题会层层放大：

- **训练显存**：除了权重本身，还要存梯度；用 Adam 这类自适应优化器时，还要为每个参数存一阶、二阶动量。显存开销远大于“只存一份权重”。
- **每个任务一份 checkpoint**：做领域适配、风格对齐、代码能力增强，各训一版就是各存一份完整模型。任务越多，存储和服务成本越高。
- **部署不灵活**：想在同一底座上切换多个任务，全量微调要求把整个模型换掉；很难做到“一个底座 + 很多小适配器”。

LoRA 论文报告，在 GPT-3 175B 上，LoRA 把可训练参数减少到原来的约万分之一、训练所需 GPU 显存约为原来的 1/3，并且合并权重后不会增加推理延迟。<Cite n={1} />它要解决的正是上面三笔账。

## 低秩分解：把权重更新拆成两个小矩阵

LoRA 的核心假设是：**微调带来的权重更新 $\Delta W$ 具有很低的内在秩（intrinsic rank）**，不需要一个完整的 $d \times k$ 矩阵来表达。于是把它分解成两个小矩阵的乘积：

$$
\Delta W = BA
$$

其中

$$
B \in \mathbb{R}^{d \times r}, \qquad A \in \mathbb{R}^{r \times k}, \qquad r \ll \min(d,k)
$$

$r$ 就是 LoRA 的**秩（rank）**，也是两个小矩阵的“中间维度”。训练时 $W_0$ 冻结，只有 $A$ 和 $B$ 可训练。加入缩放系数后的完整前向传播是：

$$
h = W_0 x + \frac{\alpha}{r} BAx
$$

这里 $x \in \mathbb{R}^{k}$ 是这一层的输入，$h \in \mathbb{R}^{d}$ 是输出。直观地说，原来的通路 $W_0x$ 原封不动，旁边多了一条“低秩修正”通路 $\frac{\alpha}{r}BAx$。

参数量对比非常直接：

| 方案 | 单层可训练参数 | $d=k=4096,\ r=8$ 时 |
|---|---|---|
| 全量微调 | $d \times k$ | $16{,}777{,}216$（约 1677 万） |
| LoRA | $r \times (d+k)$ | $65{,}536$（约 6.5 万） |

同样一层，参数量从约 1677 万降到约 6.5 万，压缩了 **256 倍**。秩 $r$ 越小，压缩越狠；这也是 LoRA 能在消费级显卡上微调大模型的原因之一。

为什么可以假设“低秩就够了”？Aghajanyan 等人的工作发现，预训练语言模型的微调过程可以被压缩到一个很低维的子空间里，而且模型越大，这个内在维度往往越小。<Cite n={2} />LoRA 把这一观察变成了结构约束：与其让优化器在 $d \times k$ 维空间里自由搜索，不如直接把它限制在秩不超过 $r$ 的子空间里。

## 缩放系数 α：为什么写成 α/r

LoRA 的前向公式里，旁路不是直接加上 $BAx$，而是乘了一个系数 $\frac{\alpha}{r}$：

$$
h = W_0 x + \frac{\alpha}{r} BAx
$$

$\alpha$ 是一个常数，实际起作用的是**乘子 $\frac{\alpha}{r}$**。它调节的是 LoRA 分支相对于原始输出 $W_0x$ 的幅度，可以理解成旁路的“等效学习率”：$\alpha$ 越大，微调更新对最终输出的影响越强。

| 参数 | 数学角色 | 实际作用 |
|---|---|---|
| 秩 $r$ | $A$、$B$ 的中间维度 | 决定旁路的信息容量。$r$ 越大，表达能力越强，但参数量、显存和过拟合风险也越高 |
| 缩放系数 $\alpha$ | 控制更新幅度的常数，实际乘子是 $\alpha/r$ | 调节 LoRA 分支对 $W_0x$ 的影响权重。$\alpha$ 越大，旁路越强 |

**为什么偏偏要除以 $r$？** 因为在常用初始化下，$BA$ 的每个元素是 $r$ 个随机项累加的结果。当你把 $r$ 从 8 调到 16，累加项变多，输出值的方差和幅度也跟着变化。如果不动学习率，模型可能突然“用力过猛”或“几乎不动”。除以 $r$ 相当于对更新量做了一次归一化：固定 $\alpha$ 时改变 $r$，旁路的整体幅度大致保持稳定，不用每换一次秩就重新大调学习率。<Cite n={1} />

工程上常见的起点是 $\alpha=16$，或者直接令 $\alpha=2r$。后者让 $\alpha/r \approx 2$ 保持恒定，换 $r$ 时最省心。不过这不是唯一选择：当 $r$ 很大时，$\alpha/r$ 会把每个秩方向的贡献压得过小，rsLoRA 提出改用 $\alpha/\sqrt{r}$ 做缩放，在高秩下往往更稳定。<Cite n={3} />所以更准确的说法是：**$\alpha/r$ 是 LoRA 原版的默认归一化方式，不是不可更改的定律。**

## 权重初始化：为什么 B=0、A 随机

训练开始时（$t=0$），LoRA 必须保证**不破坏预训练模型原本的能力**，也就是要求初始状态下

$$
\Delta W = BA = 0
$$

LoRA 的做法是：

- **矩阵 $A$**：用随机高斯分布初始化；
- **矩阵 $B$**：全部初始化为 $0$。

这样在第一步前向时，$BA=0$，输出与原始模型完全一致。但为什么不能把 $A$、$B$ 都初始化为 $0$？因为那样整个旁路会“死掉”：

- 若 $A=0$，则 $\partial \mathcal{L}/\partial B$ 里含有 $A^\top$，梯度为 $0$，$B$ 无法更新；
- 若 $B=0$，则 $\partial \mathcal{L}/\partial A$ 里含有 $B^\top$，梯度为 $0$，$A$ 也无法更新。

两个都为零，梯度互相把对方锁死，对称性无法被打破。反过来，只把 $B$ 置零、$A$ 保持随机，就同时满足两个要求：初始 $\Delta W=0$（不破坏原模型），且 $B$ 的梯度非零（第一步就能开始学习）。<Cite n={1} />

> ⚠️ **一个容易被忽略的细节**：第一步训练时，$A$ 的梯度其实仍然为零（因为 $B=0$），所以严格来说**第一步只有 $B$ 在更新**；等 $B$ 离开零之后，$A$ 才开始获得非零梯度。这不是 bug，而是这套初始化自然的结果。它保证了“先学一个小的修正方向，再让两个矩阵共同调整”。

## 推理合并：训练完就“消失”

LoRA 最漂亮的性质来自矩阵乘法的分配律：

$$
W_0 x + \frac{\alpha}{r} BAx
= \left(W_0 + \frac{\alpha}{r} BA\right)x
$$

也就是说，训练结束后可以在离线阶段直接算出

$$
W_{\text{merged}} = W_0 + \frac{\alpha}{r} BA
$$

用它覆盖原权重。之后在线推理走的就是普通的 $W_{\text{merged}}x$，**没有额外的矩阵乘法，也没有额外的显存开销**。这正是 LoRA 与 Adapter、Prefix Tuning 等方法的显著区别：后者会在推理时增加额外的层或 token，LoRA 合并后则完全“隐身”。<Cite n={1} />

下面这段代码把两件事都验证一遍：初始时 $BA=0$，以及合并前后的输出完全等价。点“运行”即可：

import numpy as np

rng = np.random.default_rng(0)

d = k = 8          # 玩具矩阵维度
r = 2              # LoRA 秩

W0 = rng.normal(0, 0.02, (d, k))    # 冻结的预训练权重
A  = rng.normal(0, 0.1,  (r, k))    # 随机初始化
B  = np.zeros((d, r))               # 关键:B 初始化为 0

x = rng.normal(size=(k, 1))

# 1) 初始状态:ΔW = BA 全零,输出与原始模型一致
h_base = W0 @ x
h_lora = W0 @ x + (alpha / r) * (B @ A) @ x
print("初始 |BA| 最大值:", np.abs(B @ A).max())
print("初始输出最大差异:", np.abs(h_base - h_lora).max())

# 2) 假设训练后 B 变成了非零矩阵
B = rng.normal(0, 0.1, (d, r))
h_lora = W0 @ x + (alpha / r) * (B @ A) @ x

# 3) 合并:W_merged = W0 + (alpha/r) B A
W_merged = W0 + (alpha / r) * (B @ A)
h_merged = W_merged @ x

print("\\n合并前后输出最大差异:", np.abs(h_lora - h_merged).max())

> ⚠️ **合并不是永远最优**。合并后的权重只对应**一个任务**，想在同一底座上切换多个适配器就不能合并；如果底座做了量化（如 4-bit），直接合并可能损失精度，通常保留 LoRA 分支单独计算。部署时是“合并成一个模型”还是“底座 + 动态加载适配器”，取决于你要的是推理速度还是多任务灵活性。

## 工程实践：目标模块、r 与 α 怎么选

真正动手微调时，比公式更容易踩坑的是配置。下面是一张常用的起点表：

| 配置项 | 常见起点 | 说明 |
|---|---|---|
| `target_modules` | 注意力层的 `q_proj`、`k_proj`、`v_proj`、`o_proj`；需要更强适配时加上 MLP 的 `gate/up/down_proj` | 原论文在 GPT-3 175B 上比较过不同组合，报告在固定参数预算下，把秩集中在注意力投影（尤其 $q$、$v$）上通常已经足够好；工程上再按任务扩散到更多线性层<Cite n={1} /> |
| 秩 $r$ | 简单任务 8–16；复杂领域适配 32–64 | $r$ 越大容量越强，但参数、显存和过拟合风险一起涨。先从小秩试起，不够再加 |
| 缩放系数 $\alpha$ | 16，或 $\alpha=2r$ | 让 $\alpha/r$ 保持在 1–2 附近是常见做法；高秩时可考虑 rsLoRA 的 $\alpha/\sqrt{r}$<Cite n={3} /> |
| 学习率 | 常从 $10^{-4}$ 量级起步 | LoRA 的可训练参数少，通常比全量微调更能承受较大的学习率；具体仍要看任务和数据 |
| LoRA dropout | 0.05–0.1 | 在旁路上加 dropout，小数据下有助于抑制过拟合 |

两个特别值得记住的组合：

1. **QLoRA = 4-bit 量化底座 + LoRA**。它把冻结的底座压到 4-bit（NF4），只让 LoRA 分支用较高精度训练，从而在单张 48GB GPU 上微调 65B 模型，并保持接近 16-bit 全量微调的效果。<Cite n={4} />这让“消费级硬件微调大模型”从演示变成了常见实践。
2. **一个底座 + 多个适配器**。同一个底座可以对应任意多个 LoRA 适配器；服务端可以按请求动态加载不同适配器，实现“一个底座服务多个任务”。代价是每个任务仍要单独训练、单独存一份小权重。

> 💡 **选型直觉**：数据少、任务窄、算力有限 → LoRA 通常是第一选择；需要大幅改变模型行为（新语言、大规模代码/数学域迁移）→ 先别假设 LoRA 一定够，必要时和全量微调做对照。

## 变体：从 LoRA 长出来的几条线

LoRA 的结构足够简单，后来很多工作都在它的两个矩阵、缩放方式和秩分配上做文章：

| 变体 | 改了什么 | 想解决什么 |
|---|---|---|
| **rsLoRA** | 把缩放从 $\alpha/r$ 改成 $\alpha/\sqrt{r}$ | 高秩时 $\alpha/r$ 会把每个方向压得太小，$\alpha/\sqrt{r}$ 让大 $r$ 也能稳定学习<Cite n={3} /> |
| **DoRA** | 把权重拆成“幅度”和“方向”，对方向做 LoRA、对幅度单独学习 | 缩小 LoRA 与全量微调之间的能力差距，低秩下通常更强<Cite n={5} /> |
| **LoRA+** | 给 $A$ 和 $B$ 设置不同的学习率（$B$ 通常更大） | 两个矩阵尺度不同，同步学习率不是最优；解耦后收敛更快<Cite n={6} /> |
| **AdaLoRA** | 不同层分配不同的秩预算，并按重要性动态调整 | 固定 $r$ 可能把容量浪费在不需要的层上<Cite n={7} /> |
| **LoRA Learns Less and Forgets Less** | 系统比较 LoRA 与全量微调 | 在代码、数学等需要大幅改变行为的任务上，LoRA 可能学得更少；但它对原能力的遗忘也更少<Cite n={8} /> |

最后一条很重要：**LoRA 不是全量微调的等价替代**。它用“低秩”换来了便宜和轻量，也接受了表达能力的上限。任务越接近原模型分布、数据越少，这个上限越不容易被碰到；任务越远、需要改变的行为越多，低秩约束就越可能成为瓶颈。

## ❓ 常见问题 FAQ

**Q：LoRA 和 Adapter、Prefix Tuning 有什么区别？**
Adapter 在 Transformer 层里插入额外的小网络，Prefix Tuning 在输入前拼一段可训练的虚拟 token；两者在推理时都会增加额外计算或序列长度。LoRA 是并行的旁路，且训练后可以合并回原权重，因此**合并后没有额外推理开销**。<Cite n={1} />

**Q：$r$ 越大越好吗？**
不是。$r$ 增大提升表达能力，但参数量、显存和过拟合风险一起上升。很多任务在 $r=8$ 到 $16$ 就已经够用；如果加大 $r$ 后验证集不涨，问题通常不在容量，而在数据质量、目标模块选择或学习率。

**Q：为什么常见做法是 $\alpha=2r$？**
因为这样 $\alpha/r$ 恒等于 2，换 $r$ 时旁路幅度不变，省去重新调学习率的麻烦。它只是经验起点，不是理论最优；高秩场景可以试 rsLoRA 的 $\alpha/\sqrt{r}$。<Cite n={3} />

**Q：只训练 $A$ 或只训练 $B$ 行不行？**
不行。$B=0$ 时 $A$ 的梯度为零，$A$ 单独训练不起来；$A=0$ 时 $B$ 的梯度也为零。两个矩阵必须配合，初始化时一个为零、一个随机，才能既保证起点等价、又打破对称性。

**Q：合并之后还能切换任务吗？**
不能。合并后的 $W_{\text{merged}}$ 已经把某个任务的更新写死进权重里；要切换任务，要么换回未合并的底座并加载另一个适配器，要么保存多份完整模型。多任务服务通常选择保留 LoRA 分支、动态加载适配器。

**Q：LoRA 能完全替代全量微调吗？**
不一定。对大多数领域适配、指令微调、风格对齐，LoRA 的性价比很高；但在代码、数学、新语言等需要大幅改变模型行为的任务上，低秩约束可能限制上限，此时全量微调仍可能更强。<Cite n={8} />稳妥的做法是先用 LoRA 快速验证，再决定是否值得上全量微调。

## 📌 小结

| 概念 | 一句话 |
|---|---|
| 低秩分解 | $\Delta W = BA$，$B \in \mathbb{R}^{d \times r}$、$A \in \mathbb{R}^{r \times k}$，$r \ll \min(d,k)$ |
| 前向公式 | $h = W_0x + \frac{\alpha}{r}BAx$，$W_0$ 冻结，只训练 $A$、$B$ |
| 参数量 | 从 $dk$ 降到 $r(d+k)$；$d=k=4096$、$r=8$ 时约 256 倍压缩 |
| 缩放系数 | $\alpha/r$ 归一化旁路幅度，换 $r$ 时不必重调学习率；高秩可用 $\alpha/\sqrt{r}$ |
| 初始化 | $A$ 随机高斯、$B=0$：初始 $\Delta W=0$，同时打破对称性、保证能训练 |
| 推理合并 | $W_{\text{merged}} = W_0 + \frac{\alpha}{r}BA$，合并后无额外推理开销 |
| 代价 | 低秩限制表达能力；任务越远，LoRA 与全量微调的差距越可能显现 |

> 🎯 **一句话记住**：LoRA = 冻结大矩阵，只学低秩旁路；$B=0$ 保证起点不破坏原模型，$\alpha/r$ 稳住更新幅度，训练完合并回去，推理零额外开销。

4. Dettmers, Pagnoni, Holtzman, Zettlemoyer (2023). *QLoRA: Efficient Finetuning of Quantized LLMs*. arXiv: [2305.14314](https://arxiv.org/abs/2305.14314). —— 4-bit NF4 量化底座 + LoRA 分支，在单张 48GB GPU 上微调 65B 模型并保持接近 16-bit 全量微调的效果。本篇 QLoRA 与合并边界讨论的来源。

6. Hayou, Ghosh, Yu (2024). *LoRA+: Efficient Low Rank Adaptation of Large Models*. arXiv: [2402.12354](https://arxiv.org/abs/2402.12354). —— 分析 $A$、$B$ 在初始化与学习动态上的尺度差异，提出为两个矩阵设置不同学习率（通常 $B$ 更大），加快收敛。本篇变体章节的来源。
7. Zhang, Chen, Bukharin, Karampatziakis, He, Cheng, Chen, Zhao (2023). *AdaLoRA: Adaptive Budget Allocation for Parameter-Efficient Fine-Tuning*. arXiv: [2303.10512](https://arxiv.org/abs/2303.10512). —— 按重要性在不同层、不同模块间动态分配秩预算，而不是所有位置使用同一个 $r$。本篇变体章节的来源。
8. Biderman, Portes, Gonzalez Ortiz, Paul, Greengard, Jennings, King, Havens, et al. (2024). *LoRA Learns Less and Forgets Less*. arXiv: [2405.09673](https://arxiv.org/abs/2405.09673). —— 系统比较 LoRA 与全量微调：在代码、数学等需要大幅改变行为的任务上 LoRA 可能学得更少，但对原能力的遗忘也更少；提醒不要把 LoRA 当作全量微调的等价替代。本篇局限性与 FAQ 的来源。
